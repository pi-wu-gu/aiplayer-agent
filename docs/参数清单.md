## ⚠️ 三个"配置写了但不生效"的坑（都踩过，务必知道）

### 1. YAML 1.1 的 `off` / `on` / `no` / `yes` 是布尔值

```yaml
permissions:
  file_mode: off        # ← 会被解析成布尔 False，不是字符串 "off"
```

旧代码 `normalize_mode()` 里 `str(False or "")` = `""` → 落回默认 **`"full"`**。
也就是说机主想**关掉**文件能力，结果变成**全开**（权限反转）。

已修（2026-10-18）：`normalize_mode()` 与 `file_ops._cfg_mode()` 都显式处理布尔
（`False → off`、`True → full/free`）。**写 `off` / `readonly` 时仍建议加引号**，一眼能看出是字符串。

### 2. 热改值会压过 yaml

`POST 8770/config` 的结果写进 `logs/daemon_state.json` 的 `config` 字段，重启自动恢复。
排查"我改了 yaml 怎么没变"先看这个字段。清空它才回落到 yaml 值。

### 3. 配置段位置

`shell` / `web` / `approval` / `destructive_file` 都在 **`permissions`** 段下，不是顶层。
`approval` 曾因读错层级导致 `enabled:false` 关不掉审批（默认值恰好等于 yaml 值，表象一切正常）。
改完务必验证"改一个值真的生效"。

浏览器开 `http://127.0.0.1:8770/`：左列运行参数（保存即热生效，写入 `daemon_state.json` 重启恢复）、

右列状态/积压/🛡 授权申请（含审核历史）。

**可热改参数共 14 项**（`GET/POST /config` 同效）：
- 运行参数（10）：`poll_interval` / `wake_interval` / `wake_check_backlog` / `review_every` /
  `review_llm` / **`review_token_budget`** / `max_rounds_per_run` / `run_cooldown` / `backlog_max` / `say_on_start`
- token 熔断（1）：**`session_token_budget`**（写 `cost_guard` 段；★拒绝 0，关闭须传 `-1`）
- 列表（3）：`bot_names` / `mention_extra` / **`noise_patterns`**

密钥（keys.yaml）不在热改列。任务收尾不发游戏消息（统计只进日志/控制台）。

> ★**热改值会压过 yaml**：`daemon_state.json` 里的 `config` 覆盖项优先级高于 `config.yaml`，
> 且重启后自动恢复。排查"我改了 yaml 怎么没变"时先看这个字段。
> 想回到 yaml 值 → 手动清空该字段或把参数改成与 yaml 一致。

## sidecar 部署（已实现，随模组分发）
- 模组 jar 内嵌 `assets/aiplayer/agent_bundle.zip`（源码 + python-embed 运行时 + wheels），
  首次启动解压到 `<游戏目录>/aiplayer-agent/<模组版本>/`；按版本目录缓存，**bundle 变了必须升 mod_version**
- 升级时保留 `keys.yaml` / `config/config.yaml` / `logs`（`inheritFromPrevious` / `preserveAndClear`）
- 模组侧 `ensure_running`：8770 已有 daemon 实例则复用，否则 `python run.py --daemon` 拉起，
  另有 watchdog 保活 → **部署换包必须先确认旧 daemon 已退出**，否则新客户端会复用跑旧代码的 daemon
- 打包：`python scripts/build_agent_bundle.py`（含内嵌运行时烟测；keys/日志/审计绝不入包）
- ★**bundle 每次重打后必须重新脱敏**：包内 `agent/config/config.yaml` 带本机真实
  `roots.shared` 路径与 `bot_names`。用 `scripts/sanitize_repo.py` 或 `filter_blob_callback.py` 的逻辑处理。
  这两个脱敏脚本**自身含明文敏感词**，已在 `build_agent_bundle.py` 的 `EXCLUDE_PARTS` 里排除，
  不得再打回包内（2026-10-18 曾漏，等于把脱敏词表一起发出去）
- ★**升级陷阱**：bundle 里的 `roots.shared` 是脱敏占位符 `<GAME_DIR>/aiplayer`。若升 `mod_version`
  让模组**解压出新版本目录**，agent 会用这个占位符当路径 → shared 根不存在 → 文件工具全废。
  升版本后第一件事：把 `aiplayer-agent/<新版本>/config/config.yaml` 的 `roots.shared` 改成本机真实路径
