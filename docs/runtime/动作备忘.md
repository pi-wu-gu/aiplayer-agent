## 挖掘（0.2.1.35 起有专用动作——旧法已废弃）
- **`{"type":"dig","x":..,"y":..,"z":..[,"timeout_ms":500-25000 默认15000][,"stop":true]}`**
  - 走 `MultiPlayerGameMode.startDestroyBlock` + 每 tick `continueDestroyBlock`，**不经按键注入**，
    不受"鼠标未抓取/窗口后台"门禁影响（★旧法 `keys ["key.attack"]` 长按在窗口后台时零进度——
    原版 `handleKeybinds` 四门禁含 `isMouseGrabbed`，窗口非前台时 `grabMouse()` 静默 no-op，2026-10-17 实锤）
  - **异步**：立即返回 `dig_started` → **必须轮询 `dig_status` 直至终态**（dig_broken/dig_timeout/dig_failed/dig_cancelled）
  - 终态也会 `ChatBuffer` 播报（聊天尾部可见）；超时报错带 `progress_stage`+hint（0 且远低于徒手工时=工具不对/不可破坏）
  - 每 tick 复检：死亡/开界面/使用物品/走远 6 格 → 立即失败带原因；连续 3 tick 空气才判破（防服务端驳回误报）
  - 距离上限 6 格；目标是空气直接回 `dig_already_air`；流体/超距/冒险模式拒绝 → `dig_err:*`/`dig_start_rejected`
- `{"type":"dig_status"}` → idle / running（progress_stage 0-9）/ 终态墓碑（带 ended_age_ms）
- ★`stop=true` 取消（新 dig 会自动取代旧的）

## 视角锁定 look_lock（0.2.1.35 起；0.2.1.36 加 face；0.2.1.37 加实体锁定；0.2.1.38 entities 输出 id）
- **`{"type":"look_lock","x":..,"y":..,"z":..[,"duration_ms":200-60000 默认5000][,"face":"up|down|north|south|east|west"]}`** —— 每 tick 自动维持朝向指定点（移动中自动跟随）
- **`face` 可选（0.2.1.36）**：把瞄准点从方块中心改为该**面中心**——`up`(+.5,+1,+.5)/`down`(+.5,0,+.5)/
  `north`(+.5,+.5,0)/`south`(+.5,+.5,+1)/`east`(+1,+.5,+.5)/`west`(0,+.5,+.5)；别名 `top`→up、`bottom`→down；
  `center`/`auto`/省略=瞄中心。★**只对整数方块坐标有效**——小数坐标=精确点模式，与 face 二选一（同时给会报错）
- 典型用途：视角需持续对准某方块某面时用（放置本身已不需要它——用 place 动作，见放置节）
- 返回与 lockStatus 均回显 `face` 字段；维持/中断语义与无 face 时一致
- **实体锁定（0.2.1.37）**：`{"type":"look_lock","target":<实体id>}`（id 来自 entities 动作——**0.2.1.38 起 entities 每项含 id/type/dist/pos**）或
  `{"type":"look_lock","target_type":"minecraft:cow"}`（64 格内最近一只）——二选一、与 x,y,z/face 互斥；
  `aim=center`（碰撞箱中心，默认）/`eyes`；每 tick 按 id 重取实体跟随（实体消失/死亡/超距 8 格 → `target_lost` 结束）
  ★无效 id 报 `look_lock_err: 找不到实体 id=...`（已卸载/超距/维度不同）
- **任何视角操作立即中断**：look/turn/mouse_move/真实鼠标移动（差值 >0.05° 检测，yaw 用 wrapDegrees 防回绕误判）
- 到期 `duration_end`（非错误）；无参调用 = 查状态（running 带 remaining_ms / ended 带 end_reason）
- 整数坐标瞄中心（+0.5）、小数瞄原点点；连带写 yRotO/xRotO 防渲染插值抖动
- 适用：移动中持续对准某方块；不需要时别开（会挡其他视角操作）

## 截图（可选能力，按需调用）
- `{"type":"screenshot"}` —— 默认注入真实 **F2**（反射 `KeyboardHandler.keyPress`），存 `<gamedir>/screenshots/*.png`
- `{"type":"screenshot","mode":"grab"}` —— 直接 `Screenshot.grab`（备用路径）
- `{"type":"screenshot","query":true}` —— 取上次截图文件名（PNG 异步落盘，约 1s 后可用）
- **不要用** `press key.screenshot` / `press key.keyboard.f2` / `keys key.screenshot`：只置 KeyMapping 状态，不触发截图
- ★**设计边界**：截图是**纯按需可调用能力** —— 不进 `state()`、不随轮次/定时自动采集、不挂任何自动流程；
  **是否调用由 agent 自己判断**。截图不改变任何游戏状态，用一次只多一个 PNG 文件

## 文件动作（shared 区 = 游戏目录 aiplayer/，★写笔记只认这组）
- **`{"type":"file_read","path":"docs/xxx.md"[,"max_chars":8000]}`** —— 读文件（返回前 max_chars 字符，带 truncated 标志）
- **`{"type":"file_write","path":"docs/xxx.md","content":"...","append":true}`** —— 写文件（append=true 追加，缺省覆盖）
- `{"type":"file_append","path":"...","content":"一行\n"}` —— 追加写的简写
- `{"type":"file_list","path":"docs"}` —— 列目录条目（名称/大小）
- **路径相对 aiplayer/ 根**（越界拒绝：realpath + 符号链接检测，Windows 小写比较）
- ★与 framework 的 file_read/file_write **不是同一组**：那两个默认根是框架目录（PCL2/agent），
  读不到也写不到 shared 区——**游戏数据/笔记/缓存一律用本组 mc_act 动作**
- `{"type":"tools"}` = 自建工具索引（tool_run 用）；`{"type":"docs"}` = 模组文档目录
- fileMode 权限轴：off 时本组全不注册；readonly 时只有 file_read/file_list/tools/docs

## 放置方块 place（0.2.1.39 起有专用动作——旧法 select+look+keys key.use 已废弃）
- **`{"type":"place","x":..,"y":..,"z":..[,"side":"up|down|north|south|east|west"][,"hand":"main|off"]}`**
  - 走 `MultiPlayerGameMode.useItemOn` **发包路径**（与真实玩家右键同链路），**不经按键注入**，
    不受"鼠标未抓取/窗口后台"门禁影响（★旧法 select+look+keys key.use 在窗口后台时**完全失效**——
    use 依赖的 mc.hitResult 与 looking_at 的 p.pick 自算不是一套，2026-10-17/18 实锤）
  - x,y,z = 要放入方块的**目标空气格**（先 block_at 确认）；返回 `place_sent` 后**必须
    `place_status` 或 block_at 复核**（约 2-3 tick 落块）：`place_placed`（附 landed 落块 id）/
    `place_failed`（附 detail 诊断）/`place_unverified`
  - ★★**玩家有碰撞箱（宽0.6高1.8）不是质点**：目标格与玩家身体重叠 → 服务端实体碰撞校验必然驳回；
    place 发起前预检并直接报 `place_err`（回传目标格/玩家双方 AABB + 脚底坐标）——先 move 走开/
    跳起或换目标格，**重试同一格永远无用**；放之前也想想这格放了会不会卡住自己/卡怪
  - 支撑面自动选：优先目标格**下方地板**顶面 → 四周墙 → 上方天花板；自动避开空气/流体/无碰撞/
    带界面方块（箱子/工作台/熔炉）/常见交互方块（按钮/门/拉杆/音符盒/蛋糕/床…）；
    `side=` 显式指定被点击面（放置位=支撑格+该面方向）；响应回传 support/face/support_dist，
    支撑面可交互时回显 `support_interactive:true`（右键可能先开界面而非放置→失败就换 side=）
  - 距离上限：脚底→支撑格底中心 ≤ block_interaction_range+1（默认 5.5 格）
  - 发起前校验（明确报错）：界面开着/使用物品中/已死亡/手持非方块（回显当前手持）/物品冷却中/
    冒险·旁观模式/目标格已有方块（空气与可替换物除外）/支撑格是空气/支撑格超距
  - 失败诊断（place_status 的 detail）：手持已变/冷却中/模式不允许/界面开着/支撑格被挖/
    支撑面带界面/玩家放置期间挪进目标格/服务端驳回（距离·碰撞·保护·特殊放置规则如草径要草方块）
- `{"type":"place_status"}`（别名 place_state）→ pending / placed（附 landed）/ failed（附 detail）/ unverified
- ★受 gameActionMode 管辖（与 press/keys/dig 同轴）：safe 起 place 缺席（place_status 只读常驻）
- 开界面仍用旧法：`look` 瞄准 + `keys key.use 700ms`（place 只管放方块，不开界面）
- **2026-10-18 实网验证全绿**（D 组 `aitest/test_place_face_live.py` 0 失败）：碰撞箱预检报错带
  AABB ✓；正常放置 place_sent→placed（108-125ms，landed 一致）→block_at 复核 ✓；显式 side= ✓；
  清理 dig ✓。环境注意：平台 y=77 摆满交互家具（床/背包/工作台/copycat…），结构层 y=76 平滑石——
  copycat 会被正确排除（有 BlockEntity/界面），且显式 side= 指向它会被 tickPlace 诊断出来
  （还会吸走一个手持物品当仿随方块）

## 容器
- `click_slot`（发包路径）→ **原版容器可用**；**维度网络终端不可用**（须 `screen_click` 真鼠标）
- `cont_button {"id":N}` → `handleInventoryButtonClick`；**切石机 N = 配方索引**，产出槽随之刷新
- `get_container`（看"容器里有什么"**只用它**）→ 每槽带 `section=container|inventory`，分区压成连续区间 `ranges`；
  另有 `cls`（ResultSlot=成品槽/ArmorSlot=装备栏…）、`pick`/`place`（mayPickup/mayPlace 探测）、`post_click`（点击后 300ms 同步态）
  - **★大输出限量参数（0.2.1.44 起，默认全关=旧行为）**：
    - `compact=true` → 只回**非空槽**且每槽只留 `index/sec/cx/cy/id/count`（背包 46 槽 ≈7KB→通常 <1KB；Sophisticated Backpacks 156 槽 ≈2.3 万字符→几百字符）
    - `only=container|inventory` → 只序列化指定区段（看容器内容/整理背包各自只看一段）
    - `max_slots=N` → 槽数上限（在 200 硬顶基础上再收紧）
    - `find=物品id子串` → 只回匹配槽（最省的精确查法，给可直接点的 cx/cy）
    - 限量生效时追加 `shown`（实回槽数）+ `truncated`（是否有槽被裁）——**`truncated=true` 必须换 `find`/`only` 分段读，禁止当"容器只有这些"**
  - ★Sophisticated Backpacks 类方块：物品按 `storage_uuid` 存服务端，**方块 NBT 不同步物品**——
    `be_nbt` 只能读到组件/升级（升级在 `render_info_tag.upgradeItems`），读实际物品必须开 GUI + `get_container`

## 权限表（mod 0.2.1.6 起五轴全生效）
- 配置在 `config/aiplayer-common.toml` 的 `[permissions]`：`fileMode`(full/readonly/off)、`commandEnabled`、`selfToolEnabled`（**0.2.1.6 起真生效**：开才注册 `tool_run` 执行自建宏）、`gameActionMode`(full/safe/observe)；出站网络是根键 `networkEnabled`
- **闸门在装配期**：被禁的动作根本不在注册表里 —— 调用会得到 `denied: xxx 被权限表禁用…`（不是 unknown）
- **改 toml 无需重启客户端**：热重载后注册表自动重建（动作名数：fileMode full 88→readonly 86→off 82；
  gameActionMode full 88→safe 76→observe 73；selfToolEnabled 开 +2）
- 自查当前模式：`{"type":"actions"}` 的 `permissions` 字段（含 deniedCount）；全局拒绝计数见 `GET /stats`
- 越界路径会落盘 `<datadir>/logs/denied_access.log`：别去试 `../` 或工作区外的绝对路径，只会留下审计记录
- 工作区 = `<gamedir>/aiplayer/`（可用 dataDirectory 改）；已硬化 realpath + 符号链接检测
